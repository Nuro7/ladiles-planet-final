2. CORE WORKFLOW — DO NOT CHANGE
============================================================

The user supplies:
- The bride identity image(s).
- Multiple views/angles of the desired bridal dress.
- The mandatory dupatta reference.
- The premium jewellery/bridal ornaments reference sheet.

The platform uses the analyzed description of the selected inspiration image to generate a scene-specific prompt.

DO NOT require the original inspiration/reference image to be attached to the generation request. The generation request should use the bride/dress/dupatta/jewellery references, not the original inspiration image.

This is an IMAGE workflow, not a video workflow. Do not add video, motion-transfer, duration, or storyboard controls to these image prompts.

3. INPUTS: REQUIRED VS NOT REQUIRED
============================================================

REQUIRED INPUTS FOR EVERY IMAGE PROMPT:
1. Bride identity image(s) — authoritative face/identity source.
2. Multiple dress reference images — authoritative garment design source.
3. Dupatta reference — mandatory; reproduce the supplied dupatta.
4. Bridal jewellery/ornaments sheet — use as a reference for premium coordinated jewellery.
5. Selected prompt ID (for example, IMAGE_01 or IMAGE_02).

NOT REQUIRED:
- The original inspiration/reference image at generation time. Analyse it beforehand and convert it into a text scene description.
- The original reference video.
- A groom image, unless a future prompt explicitly includes a groom.
- A mannequin or product image as the final scene composition. Dress photos are garment-design references only.

OPTIONAL:
- Extra bride angles, if available, to improve identity consistency.
- Extra dress angles, close-ups, or detail images to clarify embroidery and construction.
- User-selected model/settings supported by the platform.

If any mandatory input is missing, show a clear validation message instead of silently generating with missing references.

4. NON-NEGOTIABLE RULES FOR ALL PROMPTS
============================================================

A. BRIDE IDENTITY LOCK
- The supplied bride image(s) determine the bride's identity.
- Preserve face shape, eyes, nose, lips, jawline, skin tone, hairline, and distinctive features.
- Do not use the woman from the inspiration image as the generated bride.
- Do not generate a generic bride or blend identities.
- Keep natural skin texture; avoid plastic-looking skin and facial distortion.

B. EXACT DRESS LOCK
- The supplied dress images are the authority for the garment.
- Use multiple dress angles together as views of one garment.
- Preserve the actual colour, neckline, blouse construction, chest embroidery, motifs, sleeves, skirt, fabric, borders, embellishments, and construction.
- Do not redesign, recolour, simplify, or substitute the dress.
- Do not invent garment details not supported by the supplied references.

C. ANTI-MANNEQUIN LOCK — CRITICAL
Dress images may show a mannequin, white display torso, hanger, clothing stand, or product-photo background.
- Transfer the garment design only.
- NEVER transfer the mannequin into the generated image.
- NEVER add a white abdomen patch or white torso fragment.
- NEVER paste the complete product photo into the scene.
- NEVER copy the product-photo background.
- Fit the garment naturally to the real human bride.
- If the actual garment exposes the abdomen, show natural human skin; if it covers the abdomen, reproduce its actual coverage.

D. MANDATORY DUPATTA
- The supplied dupatta is required in every generated bridal image.
- Preserve its colour, fabric, transparency (if any), embroidery, motifs, borders, and embellishments.
- Drape it naturally over the bride's head/shoulders/body as appropriate to the composition.
- Do not omit it or replace it with a generic veil.
- Keep the face visible and the fabric physically plausible.

E. PREMIUM JEWELLERY
- Use the supplied jewellery sheet as a visual reference.
- Choose a coordinated, plausible set from the sheet; do not blindly place every item in a collage on the bride.
- Suitable items may include a necklace/choker, earrings, maang tikka, bangles, rings, nath, and hathphool when appropriate.
- Preserve the reference-supported design, metalwork, stones, pearls, and colours.
- Keep jewellery realistic and consistent; do not let it float, melt, or merge into skin.
- Do not unnecessarily obscure the dress neckline or important chest embroidery.

F. SCENE COMPOSITION
- The analysed inspiration image determines the written scene composition, pose, camera framing, environment, lighting, and mood only.
- Do not attach the original inspiration image to generation by default.
- Do not let the inspiration image override the supplied bride identity, dress, dupatta, or jewellery.

G. OUTPUT
- Photorealistic luxury Indian bridal campaign aesthetic.
- No added text, captions, logos, watermarks, or branding unless explicitly requested.
- Do not claim that prompting guarantees pixel-perfect identity or garment replication; keep the prompt strong while acknowledging model limits if the UI needs a user-facing note.

8. CODEX INTEGRATION REQUIREMENTS
============================================================

A. STORE PROMPTS AS DATA
Use a structured prompt registry or data file rather than scattering prompt strings throughout UI code. Each prompt should include:
- id
- displayName
- category ("bridal_image")
- status ("passed", "draft", "testing", "needs_revision")
- sceneDescription
- generationPrompt
- negativePrompt
- aspectRatio (default "4:5" for this image workflow, unless a prompt explicitly specifies otherwise)
- requiredAssets
- optionalAssets
- inspirationImageRequiredAtGeneration (false for IMAGE_01 and IMAGE_02)
- version

B. DYNAMIC ASSET ROLES — NO HARDCODED FILENAMES
Users may upload files with any filename. Map selected uploaded assets to semantic roles:
- bride_identity
- dress_reference_images[] (multiple images supported)
- dupatta_reference
- jewellery_reference_sheet
- inspiration_image (analysis input only; not sent to generation by default)
- optional groom_identity for future prompts that require a groom

Do not depend on names like bride.png, dress1.jpg, or jewellery.png. Do not infer a role from the filename alone when the UI can ask the user to assign it.

C. SEPARATE ANALYSIS INPUT FROM GENERATION INPUT
If the user supplies an inspiration image, analyse it first and turn it into a scene description. For IMAGE_01 and IMAGE_02, do NOT pass that inspiration image into the generation model. Pass the bride/dress/dupatta/jewellery assets as the generation references, plus the selected prompt text. Apply the same workflow to IMAGE_03 if it follows this established image-prompt workflow; confirm its specific asset requirements from its original prompt when available.

D. MULTI-ANGLE DRESS SUPPORT
Support multiple dress images in one garment-reference role. Do not treat each dress angle as a different outfit. The prompt must say they are different views of the same garment.

E. ENFORCE MANDATORY DUPATTA AND JEWELLERY
The dupatta and jewellery sheet are mandatory for this user's current workflow. Validate they are present before generation. Do not silently remove these requirements during prompt shortening or optimization.

F. ANTI-MANNEQUIN TEXT MUST ALWAYS BE INCLUDED
The anti-mannequin rules in Section 4C must be included in the final prompt or in a shared, reliably appended prompt component. Never remove the rules during optimization.

G. KEEP PROMPTS COMPLETE BUT AVOID DUPLICATION
Shared invariants can be stored once as reusable prompt blocks, but the final assembled prompt sent to the model must contain all applicable rules. Avoid appending the same negative prompt twice if a shared negative bundle is already automatically added.

H. MODEL CHARACTER LIMIT
Before sending a prompt, count characters using the actual assembled prompt (including shared prompt blocks and negatives). If the model has a character limit, compact repeated language without dropping mandatory constraints. Show a clear warning or shorten safely; do not submit an over-limit prompt.

I. STATUS INTEGRITY
Only set status to PASSED after the user confirms the output is good. IMAGE_01, IMAGE_02, and IMAGE_03 are user-confirmed as passed. Do not mark IMAGE_04–IMAGE_10 as passed until tested and approved.

J. PROMPT VERSIONING
Keep a version field and preserve the last approved version. When editing a passed prompt, save the previous version and mark the new one as testing until the user approves it.

K. NO FALSE GUARANTEES
Use strong identity and garment-lock language, but do not promise perfect pixel-level reproduction. The prompt is an instruction to the image model, not a guarantee.
